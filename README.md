# Podtainer

Podtainer is a browser-based container management UI, in the spirit of Portainer, built directly on Podman Quadlet and `systemd --user` instead of a container-engine socket. It runs entirely under your own user session — rootless, no service account, no installer — on the premise that systemd already handles process supervision, restarts, and logging, so Podtainer's job is just to be a legible front end over what Podman and systemd are already doing. Each stack is a plain `docker-compose.yml`; deploying one shells out to `podlet` to generate stack-prefixed Quadlet units (one `.container` per service, a shared `.network`, and a `.target` for start/stop-as-a-group), and redeploying is a pure filesystem diff against that naming convention. Podtainer keeps no database or cache of its own — every read is derived live from systemd and Podman, so changes made by hand over SSH show up in the UI with no reconciliation step.

The UI has four views: Stacks (compose-managed, with deploy/redeploy/delete/pull), and three general-purpose views — Quadlets, Systemd, and Containers — that show everything on the host of that kind, not just what Podtainer manages, so hand-authored quadlets or plain `podman run` containers show up alongside Podtainer's own. It ships as a single Go binary with an embedded Vue frontend, talks to `podman`/`podlet`/`systemctl` purely via CLI shellout, and binds `0.0.0.0` with no built-in auth on the assumption it's run on a trusted headless server.
